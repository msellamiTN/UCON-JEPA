# G7.2 — Gateway-only identity and credential mediation

## Security objective

Establish a single controlled path from an authenticated agent request to a downstream service. The gateway is the only component allowed to obtain/use downstream credentials. Agents submit an identity token and a logical operation; they do not submit downstream credentials, arbitrary target URLs, arbitrary forwarding headers, or a principal string to be trusted.

This stage is a deterministic reference contract with injected verifier, policy decision point, route registry and credential broker. It is not a production JWT/OIDC implementation, secrets manager, network proxy, or proof that deployment networking prevents bypass.

## Trust boundaries

1. **Untrusted caller:** controls bearer token bytes, logical operation, resource key and body.
2. **Identity verifier (trusted TCB):** validates signature, issuer, audience, expiry, not-before, token type and any required nonce/tenant constraints; returns a verified immutable identity.
3. **Route registry (trusted config):** maps a logical operation to a fixed service origin and path template. Caller cannot choose an origin.
4. **UCON policy decision point (trusted TCB):** evaluates subject, tenant, action, resource, context, policy version and current authorization epoch. JEPA output is advisory only.
5. **Credential broker (trusted TCB):** issues a short-lived, audience/resource/action-scoped downstream credential. The gateway never accepts a downstream credential from the caller.
6. **Gateway transport:** attaches the scoped credential and sends only to the registered target.

## Identity invariants

- A raw token is never interpreted as claims by the gateway; only the injected verifier can produce `VerifiedIdentity`.
- The verifier's configured issuer and audience are checked again by the mediator.
- Expired, not-yet-valid, empty-subject, wrong-tenant or wrong-audience identities are denied.
- The effective principal is derived from verified claims and a trusted delegation mapping, not from an arbitrary caller header.
- Forwarded identity headers from the caller are not propagated.
- A token's mere validity does not imply authorization.

## Credential invariants

- The caller cannot provide `Authorization`, `Proxy-Authorization`, API keys, cookies, or a target URL as downstream authority.
- The broker scopes credentials to service audience, action, resource and effective principal, with a short TTL.
- The credential object is opaque to the request model and redacted from repr/logging.
- The mediator does not return downstream credentials or raw upstream tokens.
- The transport receives the credential only at the last controlled hop.
- No automatic fallback to caller-supplied credentials is permitted.

## Request pipeline

`Authenticate → ResolveRoute → DeriveEffectivePrincipal → UCONAuthorize → MintScopedCredential → ConstructFixedTargetRequest → Send`.

Any failure before Send produces zero downstream requests. A JEPA recommendation is not accepted as an authorization input. The G7.1 conditional mutation adapter remains responsible for conditional mutation semantics after the gateway gate.

## Proof obligations and evidence

- **P7.2.1 (Unforgeable identity):** conditional on verifier correctness and its cryptographic trust configuration.
- **P7.2.2 (No caller authority injection):** tested for the reference request interface; production ingress must also strip/deny credential-bearing headers and network paths.
- **P7.2.3 (Fixed-target mediation):** route registry determines destination; caller has no target field.
- **P7.2.4 (Least-privilege credential):** conditional on broker enforcing audience/action/resource/principal and TTL scopes.
- **P7.2.5 (Complete mediation):** OPEN until network policy, service ACLs, credential custody and all alternate routes are proven to force gateway traversal.
- **P7.2.6 (Principal binding):** the same verified effective principal must be used by UCON, broker scope, audit record and downstream service identity.

The unit tests establish deterministic reference behavior only. They do not prove JWT cryptography, secret-manager isolation, Kubernetes network policy, service-mesh enforcement, or production complete mediation.
