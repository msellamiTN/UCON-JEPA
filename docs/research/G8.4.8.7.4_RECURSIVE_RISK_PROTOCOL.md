# G8.4.8.7.4 — Recursive future-DENY forecasting under controlled parameter shift

**Status:** implementation and focused tests added; full five-seed CI benchmark is pending. No performance result is claimed.  
**Date:** 19 November 2026.  
**Branch:** `research/g8.4.8.7.4-recursive-risk-forecasting`.  
**Parent evidence:** G8.4.8.7.3 one-step action representation results in [G8.4.8.7.3_JEPA_ACTION_RESULTS.md](G8.4.8.7.3_JEPA_ACTION_RESULTS.md).

## 1. Objective and estimand

Estimate, at a decision point, the probability that at least one of the next (H) transitions receives a formal UCON `DENY), for (H\in\{1,2,4,8\}).

For a window beginning at transition (t), the binary target is

[
Y_{t,H}=\mathbb{1}\left[\max_{j=0,\ldots,H-1} D_{t+j}=1\right],
]

where (D_{t+j}=1) exactly when the independently implemented batch policy oracle and online gate both reject the action. The dataset generator checks oracle/gate agreement at every transition. This is a future formal-denial endpoint in the synthetic environment; it is not a claim about every possible security violation in a deployed system.

## 2. Information conditions

### E1 — privileged known-action diagnostic

E1 receives the realized action sequence for the complete evaluation window and recursively predicts latent future state and per-step denial risk. It is a diagnostic upper-information condition only; future actions are unavailable at a real decision point.

### E2 — predicted-action recursive forecast

E2 receives only the initial decision-time context. At each rollout step it samples an action from its calibrated past-only action head evaluated on the recursively predicted JEPA latent. It then advances the latent state and predicts the next denial risk. The action distribution is sampled with Monte Carlo to propagate categorical action uncertainty.

E2 must not receive realized future actions, future observations, future denial labels, policy identity, rho, episode ID, step, or partition. E1's privileged input must remain isolated from E2's callable inference interface.

## 3. Data and split protocol

- Reuse the frozen G8.4.8.7.1 parameterized generator without changing its version.
- Five archetypes × three security families; 300 episodes per cell for the full benchmark.
- Train/validation/calibration use rho = 0.20, 0.40, 0.60; shifted test rho = 0.85; reverse diagnostic rho = 0.05.
- Five seeds: 20261120–20261124; fixed eight-transition episodes.
- Train-only scaling and JEPA fitting; validation for action-head model selection; nominal-support calibration only for action temperature and horizon/condition-specific risk calibration.
- Evaluate contiguous episode-local windows only. Overlapping windows are not independent; bootstrap resampling is at the whole-episode level.

## 4. Risk calibration and comparators

A separate two-parameter Platt calibrator is fitted for each horizon and each E1/E2 condition using only nominal-support calibration windows. To avoid pseudo-replication from overlapping windows, calibration uses exactly one predeclared window (start step 0) per calibration episode. The shifted and reverse-shifted tests are not used for calibration or model selection.

The initial implementation reports a horizon-matched train-prevalence baseline, E1, and E2. The prevalence baseline uses the training partition's empirical (Y_{t,H}) prevalence for the same horizon, not the single-transition denial rate.

Primary metrics: AUROC, AUPRC, Brier score, and 10-bin ECE. Report test prevalence, per-archetype/family results, E2 Monte Carlo risk dispersion, and paired whole-episode bootstrap intervals for E2-minus-E1 Brier. Lower Brier is better; a negative E2-minus-E1 difference favors E2.

The current increment does not claim that E2 is better than a matched supervised recursive state-transition model. That comparator remains a required follow-up if E2 shows promise; the prevalence baseline is deliberately weak and cannot establish JEPA superiority.

## 5. Formal authority and interpretation

Formal UCON remains the sole authorization authority. Forecasts may support advisory warning, review prioritization, or evaluation of a separately specified intervention. They cannot authorize an operation, alter the policy oracle, or override a current `DENY`.

The E1/E2 comparison measures predictive information loss under uncertainty about future actions. It does not measure intervention utility, operational latency, or production safety.

## 6. Acceptance gates

1. Full G8.4 regression suite and focused E1/E2 tests pass.
2. Five-seed full benchmark completes and retains per-seed datasets, risk calibrators, horizon metrics, subgroup metrics, and episode-bootstrap intervals.
3. No shifted test parameter enters fitting, calibration, or selection.
4. The target definition and oracle/gate agreement remain explicit.
5. Report horizon-specific and archetype-specific results; do not infer robustness from pooled metrics alone.
6. If Platt calibration sees only one class for any horizon/condition, fail explicitly rather than silently returning an uncalibrated probability.
7. Do not claim JEPA superiority without the matched supervised recursive comparator.

## 7. Explicit limitations

The current implementation is a linear JEPA reference model evaluated on five hand-designed synthetic behavior archetypes and one scalar mixture parameter per archetype. E1 is privileged; E2's recursive use assumes that predicted target latents remain compatible with the context-latent action head. Monte Carlo action sampling does not establish real-world calibrated uncertainty. Real-agent transfer, adversarial adaptation beyond the specified archetypes, intervention utility, and production authorization assurance remain open.
