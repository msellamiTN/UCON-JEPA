# G5.6 — Confirmatory evaluation and falsification protocol

**Status:** Protocol specified; no JEPA performance result is claimed.

## 1. Research questions
- RQ5.1: Does action-conditioned JEPA improve workflow-level trajectory prediction over matched supervised transition models?
- RQ5.2: Does trajectory-level risk certification control the population bad-episode rate under its IID assumptions?
- RQ5.3: What acceptance/coverage does it retain at fixed certified risk?
- RQ5.4: How does it behave under non-monotone risk, rare violations, and insufficient calibration data?
- RQ5.5: How sensitive is it to tool, policy, tenant, temporal, and environment shift?
- RQ5.6: Does predictive admission provide measurable value beyond formal UCON and temporal monitoring, after accounting for false interventions and latency?

## 2. Baselines

| ID | Method | Purpose |
|---|---|---|
| B0 | Formal UCON + temporal monitor, no predictive selection | Authoritative governance baseline |
| B1 | Heuristic risk score + no certification | Demonstrates why raw thresholding is insufficient |
| B2 | Matched supervised transition predictor + risk score | Tests JEPA-specific advantage |
| B3 | Probabilistic state-space/transition model + risk score | Alternative predictive architecture |
| B4 | JEPA + fixed-sequence Clopper–Pearson certification | Main predictive candidate |
| B5 | JEPA + simultaneous Bonferroni Clopper–Pearson certification | Non-monotone threshold alternative |
| B6 | Naive empirical threshold selection | Negative statistical baseline |

The fixed-sequence statistical method is adopted from existing selective-risk-control work, not claimed as a new generic theorem.

## 3. Data domains
1. Cloud/IAM operations: privilege changes, secret access, deployment, resource deletion, cross-account actions.
2. Banking workflows: beneficiary creation, approvals, payments, account access, sensitive-data disclosure.
3. Data governance: PII extraction, transformation, lineage, export, sharing, retention and deletion.
4. Enterprise SaaS/MCP: delegation, document access, external sharing, connector actions and session changes.

Each episode must have explicit state, action, policy version, tool version, provenance, full trace, and a reproducible binary outcome definition.

## 4. Split protocol

Split by independent episode clusters, not individual tool calls. Prevent leakage across repeated templates, tenants, principals, resources, and temporal sessions.

Use training, validation, independent pilot, calibration, and untouched confirmatory test splits. No test or calibration labels may be used to tune the predictor or score.

## 5. Primary metrics
- certified selective risk on untouched test episodes;
- calibration failure rate across repeated independent calibration trials in simulation;
- acceptance rate and NULL rate;
- risk–coverage curve;
- trajectory-level violation recall and precision;
- false intervention rate;
- per-domain and per-policy-version results;
- P50/P95/P99 end-to-end latency;
- throughput, memory, and compute cost;
- horizon-dependent state/security-feature prediction error.

Report raw numerators and denominators, confidence intervals, and calibration sample sizes. Aggregate results must not hide a dangerous domain or subgroup.

Report a one-sided confidence interval for the Monte Carlo failure probability and compare it with delta.

For real held-out episodes, report empirical test selective risk with uncertainty intervals. The finite-sample calibration theorem does not make the test estimate exact; test data remain an independent empirical evaluation.

Use multiple independent random seeds and pre-register primary configurations. Correct for multiple confirmatory comparisons where appropriate.

## 7. Stress tests
- non-monotone risk as a function of score threshold;
- no feasible safe threshold;
- rare catastrophic violations;
- correlated episodes within tenants;
- policy-version changes;
- tool schema/implementation changes;
- distribution shift in action sequences;
- missing or delayed outcome labels;
- simulator-to-real mismatch;
- predictor confident false negatives;
- OOD score concentration.

## 8. Falsification criteria

Reject or substantially revise the JEPA-centred claim if JEPA does not outperform matched supervised predictors, rollout errors grow rapidly with horizon, the score cannot separate safe and unsafe episodes, NULL decisions are too frequent, shift invalidates certification without a usable abstention response, false interventions outweigh security benefit, or latency exceeds the protected operation budget.

## 9. Claim/evidence matrix

| Claim | Required evidence |
|---|---|
| Formal authorization remains authoritative | THM-1/THM-9 and implementation gate tests |
| Revocation/policy update are race-safe | THM-2/THM-3 and model checking |
| JEPA improves trajectory prediction | B2/B3 matched controlled experiment |
| Risk is controlled under IID assumptions | G5.3 proof and simulation coverage |
| Runtime risk transfers to production | Independent sim-to-real or prospective evidence |
| Policy evolution benefits from predictive dynamics | Exact replay separated from unseen counterfactual evaluation |
| System is operationally viable | Latency/throughput/cost and failure-mode tests |

## 10. Reproducibility requirements

Commit configurations, dataset schema and hashes, environment lockfiles, seeds, scripts, raw aggregate results, analysis scripts, and run manifests. Do not commit confidential customer traces. Synthetic traces and sanitized benchmark data must be reproducible.
