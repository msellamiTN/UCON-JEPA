# G8.4.8.8 — Causal utility of predictive interventions under adaptive agent behavior

**Status:** protocol drafted; confirmatory execution is blocked pending the operational quantities listed in §13. No intervention experiment has been run and no causal effect is claimed.  
**Parent:** G8.4.8.7.7 decision-time matched recursive evaluation.  
**Research question:** when predictive risk estimates are used only to trigger a fixed, non-authoritative preventive control, do JEPA-triggered interventions improve security-relevant agent behavior and task utility compared with a directly supervised predictor, reactive UCON adaptation, and UCON enforcement without additional intervention?

## 1. Motivation and scope

G8.4.8.7.7 evaluates prediction at decision time. It does not establish that a prediction changes agent behavior beneficially. A predictive model can improve a score without improving security, or it can reduce risky behavior at unacceptable operational cost.

G8.4.8.8 therefore changes the target of evaluation from prediction quality to the **intention-to-treat (ITT) causal effect of assigning an intervention strategy**. The intervention mechanism is identical for JEPA and supervised prediction; only the trigger differs. All experimental arms retain the same authoritative UCON enforcement.

This is a synthetic, controlled policy-evaluation study. It is not a production deployment, human-subject study, or claim that simulated DENY attempts equal real security breaches.

The confirmatory question is **intervention utility**, not whether JEPA is intrinsically superior as a representation learner. No JEPA superiority claim is permitted unless the JEPA-versus-supervised contrast supports it under the frozen analysis and all utility guardrails pass.

## 3. Experimental arms

Randomize independent agent episodes to one of four mutually exclusive strategies:

| Arm | Strategy | Trigger and behavior |
|---|---|---|
| A0 — UCON-only / no prediction | Base formal UCON enforcement; no additional anticipatory or DENY-triggered intervention. | Every proposed tool operation is evaluated by the current UCON policy. |
| A1 — Reactive UCON | Non-predictive event-triggered adaptation. | After the first observed UCON DENY in an episode, apply the standardized temporary least-privilege overlay at the next eligible decision. |
| A2 — JEPA-triggered | Frozen JEPA E2 future-DENY risk score. | Apply the same overlay at the first eligible decision whose score crosses a threshold frozen on validation data. |
| A3 — Supervised-triggered | Frozen directly supervised recursive risk model from the matched-control family. | Apply the identical overlay using its own validation-frozen threshold. |

A0 and A1 are intentionally distinct: A0 is the no-additional-intervention baseline; A1 tests a reactive strategy that uses only an already observed policy event. The base UCON authorization check remains active in **all four arms**.

### 3.1 Standardized intervention

The intervention is a temporary, task-manifest-defined least-privilege overlay:

1. At a trigger, temporarily remove the episode's predeclared *nonessential high-risk tool capabilities* from the agent's available action set for the next two decision opportunities.
2. Do not change the formal UCON policy, policy decision point, identity, or authorization result.
3. Do not add privileges, mint credentials, convert DENY to PERMIT, or skip authorization.
4. Restore the original capability set after the two decision opportunities, subject to current UCON policy and revocation state.
5. Record trigger reason, model/policy version, overlay start/end, suppressed proposals, and restoration outcome.

The task manifest and essential/nonessential tool classification must be fixed before test generation. The overlay is a restrictive orchestration control, not an authorization decision. Every operation that reaches a tool still passes through UCON.

At most one overlay is applied per episode. The two-decision duration is fixed for all arms. No arm may receive a stronger or longer intervention.

### 3.2 Trigger thresholds and intervention frequency

For A2 and A3, fit no model on test data. For each validation episode, compute the maximum model risk score over its eligible decision points. Set the model-specific threshold to the 90th percentile of these episode maxima, so the validation operating point targets 10% of episodes. Resolve ties with a deterministic, predeclared hash-based ordering. In a test episode, apply the overlay at the first eligible decision whose score crosses the frozen threshold; at most one overlay is allowed per episode. Freeze thresholds before test assignment/outcome inspection.

The 10% value is a **design operating point**, not an empirically established optimum. Report realized test intervention rates under shift; do not retune thresholds to force test rates to match. A1 triggers on the first DENY and is subject to the same one-overlay-per-episode cap; its realized rate may be lower or higher than the predictive arms' realized rate. Intervention count and burden are outcomes, not silently equalized after observing test behavior.

Report a predeclared sensitivity analysis at alternative validation operating points of 5% and 20%, clearly secondary. These thresholds are selected on validation only and are not used to select a favorable confirmatory result.

## 4. Population, simulator, and data separation

Use the existing G8.4 stateful policy-conditioned synthetic environment as the initial testbed, retaining its five behavior archetypes and three security families. The confirmatory dataset must be generated independently of the G8.4.8.7.7 test episodes.

- Train, validation, calibration, and confirmatory test episodes are disjoint by episode and synthetic agent identity.
- One independent agent identity contributes to one randomized episode only. If implementation requires repeated episodes per identity, randomize and analyze at identity-cluster level; do not treat episodes as independent.
- Block randomization by behavior archetype, security family, task difficulty, and environment seed. Keep shifted and reverse-shift conditions separate.
- Primary condition: within-archetype shifted parameter regime corresponding to rho = 0.85. Reverse rho = 0.05 is a prespecified secondary stress condition. Nominal support is used for model fitting/calibration only.
- Reuse the frozen JEPA and supervised model definitions, inference information boundaries, and training budgets from G8.4.8.7.7. Refit only on the newly generated training partition using frozen hyperparameters and the declared seed schedule; no test-driven architecture, calibration, threshold, or hyperparameter selection.
- Use the same episode horizon and policy oracle semantics across all arms. The generator, task manifests, tool-capability classifications, and intervention transition semantics must be versioned and checksummed before confirmatory assignment.

The predictor may use only information available at the decision time: current permitted context, prior observations/actions, and its own recurrent/predicted state. It must not receive future actions, future observations, future policy labels, future DENY outcomes, test arm outcomes, or oracle labels.

## 5. Security and authorization invariants

For every attempted tool execution in every arm:

\[
\operatorname{Execute}(r,t) \Rightarrow
\operatorname{UCONAllow}(s_t,r,\pi_t)
\land \operatorname{OverlayAllows}(r,t).
\]

Here UCON evaluates the current subject, object, action, context, obligations, and current policy version. The overlay may further restrict an action; it cannot make an otherwise denied action executable.

Required invariants:

- **I1 — UCON authority:** no predictor or intervention component can return PERMIT or override DENY.
- **I2 — Reauthorization:** every tool call is checked against current UCON state and policy version; no cached authorization survives a relevant state change.
- **I3 — Monotone restriction:** an overlay can only remove capabilities from the manifest-defined available set; it cannot add capabilities.
- **I4 — Revocation dominance:** a revocation or policy update takes effect according to the UCON runtime contract even while an overlay is active or expiring.
- **I5 — Fail-safe boundary:** predictor/telemetry failure falls back to A0 behavior, while UCON enforcement remains mandatory. Failure to apply an overlay never creates a bypass around UCON.
- **I6 — Auditability:** every trigger, suppression, UCON verdict, overlay transition, expiry, and failure is traceable to episode, model, policy, and configuration versions.

The primary outcome counts agent proposals before the overlay filter. For measurement only, the policy oracle may label each proposed action as PERMIT/DENY under the contemporaneous state, including proposals suppressed before tool invocation. Oracle labels are not inference inputs and cannot affect the agent or treatment assignment. The simulator must log the agent's proposed action before applying the overlay; an action that the agent never proposes because the capability is unavailable is not counted as a proposal.

A zero count of executed unauthorized operations is a required invariant, not evidence that the predictive intervention caused the zero. If any arm executes a UCON-DENY operation, stop the experiment, preserve the trace, and treat the run as a safety failure.

## 6. Outcomes and estimands

Let \(i\) index an independently randomized agent episode and \(a\in\{0,1,2,3\}\) denote assignment to A0–A3. Let \(Y_i(a)\) be the potential outcome under assignment \(a\), with all outcomes measured over the same fixed episode horizon.

### 6.1 Primary security endpoint

\[
Y_i^{U}(a)=\sum_{t=1}^{T_i}
\mathbf{1}\{\text{the agent proposes an operation whose contemporaneous UCON oracle verdict is DENY}\}.
\]

This is the **policy-violating proposal burden**. It includes proposals suppressed by the overlay and proposals that reach UCON and are denied. It measures attempted policy-violating behavior, not successful compromise, data exfiltration, or realized security loss.

Primary ITT contrasts in the shifted condition:

\[
\tau_{J0}=\mathbb{E}[Y^U(2)-Y^U(0)],\quad
\tau_{JR}=\mathbb{E}[Y^U(2)-Y^U(1)],\quad
\tau_{JS}=\mathbb{E}[Y^U(2)-Y^U(3)].
\]

Negative values favor JEPA-triggered intervention. The principal architecture-specific contrast is \(\tau_{JS}\); \(\tau_{J0}\) and \(\tau_{JR}\) quantify utility against no-additional-intervention and reactive controls.

The estimand is marginal mean difference per randomized episode (ITT), not a per-trigger effect and not a model-conditional prediction metric.

### 6.2 Utility and harm guardrails

Report, by arm and as randomized contrasts:

- legitimate task completion rate and time-to-completion;
- essential-operation failure and task abandonment;
- total UCON DENY decisions and repeated DENY/retry sequences;
- proposals suppressed by the temporary overlay, separated into oracle-PERMIT and oracle-DENY proposals;
- number and duration of overlays; intervention burden per episode;
- tool calls, latency, and compute/token cost;
- executed operations with UCON DENY (must be exactly zero).

A reduction in \\(Y^U\\) is not a useful result if it is obtained by indiscriminately preventing legitimate work. Let \\(L_i(a)\\) indicate legitimate task completion and define \\(\\tau^L_{Ja}=\\mathbb{E}[L_i(2)-L_i(a)]\\) for each comparator \\(a\\). JEPA is non-inferior on task completion only if the lower confidence bound for each required contrast exceeds \\(-\\delta_L\\). Before confirmatory execution, a domain owner must specify the maximum acceptable absolute loss \\(\\delta_L\\) and the minimum meaningful reduction \\(\\delta_U\\) in DENY-labelled proposals. These margins must be frozen without access to confirmatory outcomes.

### 6.3 Secondary diagnostics

- False-intervention rate: proportion of triggered episodes whose paired no-overlay shadow trajectory has no UCON-DENY proposal in the next prespecified horizon. Fork the simulator state immediately before the trigger and replay the same exogenous random-number stream without the overlay. This is a diagnostic based on a simulator counterfactual, not the primary randomized causal endpoint.
- Trigger precision/recall and calibration, reported separately from intervention outcomes.
- Heterogeneity by archetype, security family, and shift condition. These are secondary; no subgroup superiority claim without multiplicity control and adequate precision.
- 5% and 20% validation operating-point sensitivities.
- Reverse-shift condition (rho = 0.05).

## 7. Causal identification and analysis

### 7.1 Assignment

Randomize at the independent agent-episode level, using permuted blocks within seed × archetype × security-family × task-difficulty strata. Use equal allocation 1:1:1:1. Assignment is generated before episode execution and concealed from the simulator's outcome evaluator. The same identity or trajectory must never cross arms. This is baseline randomization among complete strategies (a strategy-level trial), not a micro-randomized trial: the estimand compares assignment to the entire adaptive rule. A micro-randomized design would be appropriate only for a different question about the proximal effect of randomizing the overlay at each eligible decision point under a specified prior treatment schedule.

### 7.2 Identification assumptions

The ITT contrasts are identified by the randomized design if:

1. **Consistency:** the implemented arm corresponds to its versioned strategy and intervention semantics.
2. **Randomization:** assignment is independent of all potential outcomes within the declared randomization blocks.
3. **No interference:** one episode's assignment does not alter another episode's agent state, policy state, resource availability, or outcomes.
4. **Positivity:** every arm has nonzero assignment probability in every included randomization block.
5. **Outcome ascertainment:** proposal and oracle logs are complete and arm-independent.
6. **No differential censoring:** episode termination or missingness is not silently treated as success; all terminations and failures are retained and classified.

These are design assumptions to test/audit where possible, not mathematical facts established by the protocol alone.

### Identification proposition (conditional)

Let \(B_i\) be the pre-assignment randomization block, \(A_i\) the assigned arm, and \(Y_i(a)\) the potential episode outcome under strategy \(a\). Suppose (i) consistency, (ii) \(A_i\perp (Y_i(0),\ldots,Y_i(3))\mid B_i\), (iii) \(\Pr(A_i=a\mid B_i=b)>0\) for every included arm/block pair, and (iv) no interference between randomized units. Then
\[
\mathbb{E}[Y_i(a)]
=\sum_b \mathbb{E}[Y_i\mid A_i=a,B_i=b]\Pr(B_i=b).
\]
Consequently, the block-standardized difference in observed arm means identifies
\(\mathbb{E}[Y_i(a)-Y_i(a')]\) for any two arms \(a,a'\), over the prespecified target distribution of blocks.

**Proof.** By consistency, \(Y_i=Y_i(A_i)\). Conditional randomization gives
\[
\mathbb{E}[Y_i\mid A_i=a,B_i=b]
=\mathbb{E}[Y_i(a)\mid A_i=a,B_i=b]
=\mathbb{E}[Y_i(a)\mid B_i=b].
\]
The second equality follows from conditional independence of assignment and all potential outcomes within block. Average both sides over the target block distribution and subtract the corresponding identity for \(a'\). Positivity ensures each conditional arm mean is estimable in every target block. No-interference and consistency ensure that \(Y_i(a)\) is a well-defined outcome for the assigned strategy. \(\square\)

This identifies the **strategy-assignment ITT effect**. It does not identify the effect among episodes actually triggered, the effect of an overlay in isolation, or the effect of changing a single decision-point action while holding all later decisions fixed. Those require additional estimands/designs (for example, sequential randomization and causal excursion effects).

### 7.3 Estimation and inference

- Primary estimator: block-adjusted difference in mean episode-level \(Y^U\) under ITT assignment.
- Primary uncertainty: randomization-based inference respecting the actual blocked assignment; report 95% confidence intervals and exact randomization procedure/configuration.
- Robustness: episode-level bootstrap stratified by randomization blocks; if assignment is clustered by identity, resample identity clusters.
- Use a family-wise two-sided alpha of 0.05 across the three JEPA contrasts, with Holm adjustment. Report unadjusted estimates and adjusted p-values/interval procedure transparently.
- Analyze every randomized episode in its assigned arm. Per-protocol or as-treated analyses are secondary and explicitly non-randomized.
- Report absolute mean differences and relative rate ratios only as secondary measures; do not substitute a favorable ratio for the prespecified mean-difference endpoint.
- Publish the complete arm × seed × archetype × family tables, not only pooled averages.
- Treat environment seeds as design strata/replications. Do not present a handful of simulator seeds as a population-level hierarchical confidence interval.

### 7.4 Sample size and power

Do not choose a convenient episode count after seeing outcomes. Before confirmatory generation:

1. Define a domain-meaningful minimum reduction \(\delta_U>0\) in mean policy-violating proposals per episode.
2. Define the maximum acceptable task-completion loss \(\delta_L\) for the non-inferiority guardrail.
3. Run an arm-blinded engineering/variance pilot on separate episodes to estimate endpoint dispersion, block sizes, and any clustering. Pilot episodes are excluded from confirmatory analysis.
4. Compute sample size for 90% power at family-wise alpha 0.05 for the three planned JEPA contrasts, using a conservative multiplicity adjustment or simulation of the exact blocked randomization and Holm procedure. Use the more demanding requirement from the security endpoint and task-completion guardrail.
5. Freeze the resulting per-block and total sample sizes, seed list, and stopping rule before generating confirmatory test outcomes.

For orientation only, a simple equal-arm mean-comparison approximation is
\[
n_{\text{per arm}} \approx
\frac{2\sigma_U^2(z_{1-\alpha^*/2}+z_{1-\beta})^2}{\delta_U^2},
\]
where \(\alpha^*\) is a conservative per-contrast level, \(1-\beta=0.90\), and \(\sigma_U^2\) is estimated from the independent blinded pilot. This approximation is not the final sample-size calculation when count overdispersion, blocking, or clustering materially affects power.

No confirmatory test is permitted until \(\delta_U\), \(\delta_L\), the intervention semantics, and the sample-size calculation are frozen.

## 8. Falsification, negative controls, and adversarial cases

Required before confirmatory run:

- **No-trigger negative control:** thresholds set above all validation scores must produce no predictive overlays; A2/A3 should reduce to A0 with respect to overlay actions.
- **Random-trigger control:** a validation-frozen random trigger with the same expected intervention rate tests whether any apparent benefit is merely generic intervention friction. Run this as a separate, non-confirmatory negative-control pilot (or explicitly expand and re-power the randomized arm set before freeze); do not silently add it to the four-arm confirmatory analysis.
- **Label permutation:** permuting training/validation DENY labels must destroy meaningful risk-trigger alignment; it must not create a favorable confirmatory effect.
- **Score permutation:** shuffling episode risk scores before thresholding tests whether ranking information matters.
- **Oracle leakage test:** instrumented predictor inputs must not contain future action, future state, policy oracle labels, or outcome fields.
- **Authorization mutation tests:** force UCON DENY, revocation, policy-version change, predictor crash, overlay expiry, duplicate trigger, and stale context; no unauthorized execution may occur.
- **Overlay monotonicity tests:** property tests verify that the overlay never expands the tool set and expires exactly as specified.
- **Adversarial agent behavior:** retry after DENY, switch tools, split an operation, change goal wording, use an alternative identity, and exploit overlay expiry. Any cross-identity or shared-state effects invalidate the no-interference design and require redesign.
- **Task-utility counterexamples:** episodes where essential work requires an optional/high-risk tool must expose false-positive utility costs rather than being excluded post hoc.

All negative-control results and failed runs must be retained.

## 9. Reproducibility and artifact contract

The confirmatory artifact must retain:

- frozen protocol and protocol SHA-256;
- generator, policy oracle, task manifests, capability classifications, and intervention code/configuration;
- model architecture/configuration, training logs, checkpoint hashes, calibrators, validation thresholds, and inference feature manifests;
- randomization seed, block assignments, assignment audit, and arm-blinding record;
- per-episode raw proposal traces, UCON verdicts, overlay events, task outcomes, termination reasons, and cost/latency metrics;
- primary and secondary outcome tables, ITT contrasts, randomization inference outputs, confidence intervals, multiplicity adjustments, and subgroup diagnostics;
- all negative-control, mutation, and failed-run outputs;
- runtime/dependency versions, exact commands, hardware, wall time, and artifact checksums.

Every analysis must be reproducible from immutable episode-level logs. Aggregate tables alone are insufficient.

## 10. Interpretation boundaries

A positive result may support only a claim that, in this specified synthetic environment and under the tested randomized intervention strategies, assignment to one strategy changed the measured policy-violating proposal burden and task utility.

It does **not** establish:
- prevention of real security breaches or successful exfiltration;
- production authorization assurance or correctness of an external UCON adapter;
- generalization to real autonomous agents, users, organizations, or unseen policy languages;
- that JEPA is necessary, superior in general, or better than all supervised alternatives;
- human acceptance, operational feasibility, or real-world intervention compliance;
- a causal effect outside the randomized population and simulator intervention mechanism.

If JEPA and supervised-triggered intervention are equivalent within the prespecified meaningful-effect margin, the correct conclusion is that predictive intervention may have utility while JEPA-specific incremental value remains unestablished.

## 12. Execution sequence and acceptance gates

1. Implement the intervention state machine and prove its restriction/expiry properties with unit/property tests.
2. Implement four arm strategies behind one shared UCON enforcement path.
3. Add independent episode-level assignment, immutable logs, and a blinded outcome evaluator.
4. Validate all negative controls, authorization mutations, and oracle-leakage tests on small pilot episodes.
5. Run the separate blinded variance/engineering pilot; finalize \(\delta_U\), \(\delta_L\), sample size, and exact seed/block schedule.
6. Freeze protocol, source commit, configuration hashes, model checkpoints, thresholds, and test partition.
7. Execute the confirmatory randomized experiment once; no test-driven retuning or selective reruns.
8. Independently audit assignment integrity, outcome logs, checksums, statistical analysis, and interpretation before updating the claim ledger.

Acceptance requires all of the following:
- complete G8.4 regression suite passes;
- intervention and UCON invariants pass unit/property/adversarial tests;
- no future/oracle leakage;
- negative controls behave as expected;
- all four arms execute under the same simulator and UCON path;
- sample-size and multiplicity procedures are frozen;
- all randomized episodes and failures are retained;
- reproducible artifact and exact commit/workflow evidence exist;
- conclusions respect the interpretation boundaries in §10.

## 13. Blocking decisions before confirmatory execution

These are deliberate scientific freeze gates, not details to infer from the existing predictive benchmark:

1. **Meaningful security effect:** domain-approved \(\delta_U\), minimum reduction in DENY-labelled proposals per episode.
2. **Task-utility margin:** domain-approved \(\delta_L\), maximum acceptable absolute loss in legitimate task completion.
3. **Intervention manifest:** exact nonessential/high-risk capabilities per task family, and evidence that the essential capability set is complete.
4. **Simulator response semantics:** exact rule by which temporary capability narrowing affects the agent's available action set and how the agent observes that change.
5. **Sample size:** blinded pilot variance, block allocation, total episodes, seed schedule, and stopping rule.
6. **Training freeze:** exact model-training seed schedule, deterministic checkpoint-selection rule (validation only), software versions, and checkpoint hashes must be frozen before confirmatory test generation. Models are retrained on the new, disjoint training partition with the frozen G8.4.8.7.7 architecture and hyperparameters.

Until these six items are frozen and committed, G8.4.8.8 is **protocol-specified but not execution-ready**. No confirmatory dataset may be generated and no intervention-utility claim may be made.
